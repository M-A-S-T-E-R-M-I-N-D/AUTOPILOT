What it does

A standalone, open-source, cross-platform TypeScript agent. It locks onto a project folder, researches and understands it, stands up its own control panel, then flies the repo — improving it, finding bugs, closing security holes, documenting, charting, detecting anomalies, and managing versions. A local web dashboard drives it all. Multi-project, with optional local (Ollama) models, and one-command install from zero.

How it works

AUTOPILOT's unit of work is a firing — one gated attempt at one task: orient, pick one task, implement it, run the gate (typecheck · lint · test · build), and either commit on green or revert on red. Every firing is recorded to local SQLite telemetry — gate verdict, cost, tokens, and the commit-on-HEAD check — mechanically verified, never self-reported.

Nothing lands unverified

A firing that fails the gate reverts — bad work never reaches your history.

Fleets parallelize it

N lanes fly in isolated git worktrees; a self-healing merge ladder collects them with zero overwrites.

Telemetry can't flatter itself

Load-bearing numbers are mechanically verified and published in the living self-study paper.

Humans keep the human calls

Dependency changes, publicity, and spending queue for your approval in the dashboard's KEEPER panel.

Can it hurt my repo?

The first question anyone should ask an agent that edits code, answered in order of importance:

  • Backup before first touch — locking onto a repo snapshots it first.
  • Everything is a git commit — no force-pushes, no history rewrites, no touching remotes on its own.
  • Nothing lands unverified — the gate runs before every commit; red means revert.
  • Landing is your click — merging to main is an explicit operator action, never automatic.
  • Containment is seatbelts, not a cage — isolated worktrees and a containment guard, stated plainly as not a kernel sandbox.
  • Nothing phones home — telemetry is a local SQLite file; no analytics, no tracking.

Honest about alpha

AUTOPILOT is public before 1.0 on purpose, for real-world testing while the system is still forming. It's a 0.x alpha: APIs, the dashboard, and flight rituals may change without migration paths. Every commit requires a DCO sign-off, PRs merge only through a gated review ritual, and dependency/security-sensitive changes always queue for a human. Use it on code you have backups of.
